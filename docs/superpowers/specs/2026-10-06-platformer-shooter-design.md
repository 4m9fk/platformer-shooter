# Platformer Shooter: дизайн первой версии

Дата: 2026-10-06. Статус: согласован в обсуждении, ждёт ревью.

## 1. Цель

Мобильный платформер для ребёнка. Герой: уже нарисованный мальчик с бластером
(спрайты в `generated/sprites/`). Игрок бежит слева направо, стреляет по зомби,
ломает ящики и добегает до флага. Успех первой версии: один уровень, который
весело пройти на телефоне; игра ставится на домашний экран и запускается
офлайн; выкладывается на GitHub Pages одной командой `git push`.

Не входит в первую версию: жизни, очки, несколько уровней, звук, сохранение
прогресса, боссы, меню настроек.

## 2. Технологии и структура

- Phaser 3 (npm), Arcade Physics, TypeScript, Vite.
- PWA через `vite-plugin-pwa` (`registerType: 'autoUpdate'`).
- Деплой: GitHub Actions → GitHub Pages (official `actions/deploy-pages`,
  без ветки `gh-pages`). Репозиторий `git@github.com:4m9fk/platformer-shooter.git`,
  `base: '/platformer-shooter/'` в Vite.
- Тесты: Vitest для чистой логики.

Репозиторий: корень `game-1`. В git попадают исходники игры, инструменты и
`generated/sprites/` (готовые кадры). Не попадают: сырые листы генерации в корне
(`*.png`), `walk_fix/`, `generated/anim/`, `node_modules`, `dist`, `.idea`.
Старое демо `game/` остаётся как есть, игра на него не ссылается.

## 3. Спрайты и атлас

Текущие листы шириной до 4496 px не влезают в лимит текстуры 4096 px на части
телефонов, а высота кадра 512 px избыточна для экрана высотой 540. Поэтому
новый скрипт `tools/pack_atlas.py`:

1. Берёт кадры из `generated/sprites/png/<anim>_right/frame_N.png`
   (только `right`; `left` получаем через `flipX`).
2. Уменьшает каждый кадр в 2 раза: ячейка 562×512 → 281×256.
3. Укладывает все 22 кадра (idle 4, walk 8, jump 6, shoot 4) в один PNG
   не шире 2048 px и пишет JSON в формате Phaser JSON Hash с именами кадров
   `idle_0 … shoot_3`.
4. В JSON добавляет `meta.game`: ячейка, якорь ног `anchor` и точка дула
   `muzzle` из `sprites.js`, уже уменьшенные в 2 раза, плюс fps анимаций.

Тот же скрипт с параметром упакует зомби, когда появятся его кадры. До этого
Zombie использует текстуру-заглушку из `placeholders.ts` (зелёный «робот»
тех же габаритов). Переключение на атлас: замена ключа текстуры в конфиге,
логика не меняется.

Масштаб героя на экране: `HERO_SCALE = 0.7` от уменьшенной ячейки
(рост примерно 180 px, три тайла). Origin спрайта ставится в якорь ног.
Физическое тело уже ячейки: ширина около 40% ячейки, высота от макушки до ног.

## 4. Уровень

Логический экран 960×540, тайл `TILE = 60` px: ровно 16×9 тайлов на экране.
Уровень 70 тайлов в ширину (4200 px), 9 строк в высоту. Камера следует за
героем с ограничением по границам уровня и небольшим опережением по ходу.

Формат карты: массив строк в `levels/level1.ts`, одна строка на ряд, один
символ на тайл.

| Символ | Значение |
|---|---|
| `.` | пусто |
| `#` | земля, сплошной блок |
| `=` | платформа, можно запрыгнуть снизу (one-way, `checkCollision.down` только) |
| `C` | ящик, ломается выстрелом, твёрдый для героя и зомби |
| `Z` | зомби, стоит на тайле под ним |
| `F` | флаг, финиш |
| `P` | старт героя |

`levels/parse.ts` превращает строки в `{ solids, platforms, crates, zombies,
flag, start }` с координатами в тайлах и валидирует: ровно один `P`, ровно
один `F`, все строки одной длины. Ошибка парсинга бросает исключение с
номером строки и столбца.

Первый уровень по содержанию: разгон по земле, пара ям, лестница из ящиков,
платформы на двух высотах, пять зомби на разных платформах, флаг на возвышении.
Ямы: падение ниже уровня возвращает героя на старт (см. §6).

Фон: параллакс в стиле демо `game/game.js`: небо градиентом, два слоя холмов,
облака. Рисуется один раз в текстуры через Graphics, слои двигаются с
коэффициентами 0.2 и 0.5. Платформы, земля, ящики и флаг тоже
Graphics-текстуры в `placeholders.ts`, одна функция на объект, чтобы заменить
на PNG точечно.

## 5. Герой

Машина состояний как в демо:

- `idle`: стоит; `walk`: бежит со скоростью 220 px/s.
- `jump`: фазы `crouch` (0.08 с, кадр 0) → `air` (кадры 1–4 по вертикальной
  скорости: взлёт 1–2, вершина 3, падение 4) → `land` (0.12 с, кадр 5).
  Начальная скорость 700 px/s, гравитация 1800 px/s². В воздухе можно
  двигаться по горизонтали. Короткое нажатие даёт меньший прыжок: при
  отпускании кнопки на подъёме вертикальная скорость режется вдвое.
- `shoot`: 4 кадра на 10 fps, стоит на месте; снаряд вылетает на кадре 2 из
  точки дула с учётом `flipX`. Повторное нажатие ставится в очередь, так что
  удерживание даёт очередь выстрелов. Стрелять в прыжке в первой версии
  нельзя (нет кадров), кнопка в воздухе игнорируется.

Снаряд `Bolt`: синий прямоугольник со свечением, 900 px/s, живёт 1,2 с,
исчезает при касании земли, ящика или зомби, оставляет искры (частицы).

Направление: `flipX` по последнему нажатому направлению; при `flipX` тело
физики смещается симметрично, чтобы герой не «прыгал» при развороте.

## 6. Зомби, ящики, финиш, смерть

Зомби патрулирует со скоростью 60 px/s. `patrol.ts`: чистая функция
`nextDirection(dir, blockedAhead, groundAhead)`: разворот при стене или если
впереди нет земли. Проверку делает GameScene по сетке из парсера:
`isSolid(col, row)` для тайла впереди на уровне ног и для тайла под ним.
Тайлы уровня хранятся как статическая группа спрайтов, а не Tilemap.

Поражение зомби: любой снаряд или приземление героя сверху (контакт, когда
герой падает и его ноги выше середины зомби). Зомби играет `hit`
(с заглушкой: мигает и уменьшается через tween 0,4 с), исчезает, счётчик
растёт. Герой при прыжке сверху получает отскок 400 px/s.

Касание зомби сбоку: герой мигает 0,3 с, экран коротко темнеет, герой
переносится на старт уровня, зомби и ящики не восстанавливаются. Падение в
яму: то же самое. Жизней нет, игра не заканчивается поражением.

Ящик: `C`, статический, ломается от снаряда с разлётом 6 обломков
(Graphics-текстура), после этого проходим.

Флаг: при пересечении зоны герой останавливается, играет `idle`, UI показывает
экран «Победа» с числом зомби и кнопкой «Ещё раз», которая перезапускает
GameScene.

## 7. Управление

`input/Intent.ts` собирает состояние `{ left, right, jump, shoot }` из
клавиатуры (стрелки, WASD, пробел) и тач-кнопок. Hero читает только Intent.

Тач-кнопки живут в `UIScene` поверх игры, полупрозрачные круги диаметром
110 px с отступом 24 px от краёв: слева «←» и «→», справа «прыжок» (выше) и
«огонь». Каждая кнопка отслеживает свой pointer по `pointerId`, поэтому
бег, прыжок и стрельба работают одновременно. Зона кнопки больше рисунка
на 20 px. `pointerout` отпускает кнопку. На устройствах без тача (есть
клавиатура и нет `ontouchstart`) кнопки не показываются.

Жесты браузера: `touch-action: none` на canvas, запрет zoom через viewport,
`user-select: none`. Во весь экран не переходим автоматически: кнопка «⛶»
в углу вызывает `scale.startFullscreen()` там, где поддерживается.

## 8. PWA и деплой

Манифест: name «Platformer Shooter», `display: standalone`,
`orientation: landscape`, `theme_color`/`background_color` под цвет неба,
иконки 192 и 512 из кадра `idle_0` на круглом фоне (делает `pack_atlas.py`
отдельной командой `--icons`). Apple: `apple-touch-icon`,
`apple-mobile-web-app-capable`.

Workbox: precache всех файлов `dist` (`globPatterns: ['**/*.{js,css,html,png,json,svg,webmanifest}']`),
`maximumFileSizeToCacheInBytes` 6 МБ, `navigateFallback: index.html`.
Обновление: `autoUpdate`, новая версия подхватывается при следующем запуске.

Ориентация: если `innerHeight > innerWidth`, UIScene показывает оверлей
«Поверни телефон» и ставит игру на паузу; при повороте оверлей скрывается.
Попытка `screen.orientation.lock('landscape')` делается при первом касании и
молча игнорирует отказ.

Деплой `.github/workflows/deploy.yml`: на push в `main` ставит Node 20,
`npm ci`, `npm run build`, загружает `dist` артефактом и публикует через
`actions/deploy-pages`. В настройках репозитория источник Pages: GitHub
Actions. Адрес игры: `https://4m9fk.github.io/platformer-shooter/`.

## 9. Тестирование

Vitest, без запуска Phaser:

- `levels/parse.test.ts`: разбор карты, координаты объектов, ошибки на
  неровные строки, отсутствие `P`/`F`, два `P`.
- `entities/patrol.test.ts`: разворот у стены, у обрыва, движение дальше.
- `input/Intent.test.ts`: клавиатура и тач складываются через ИЛИ, отпускание
  одного источника не гасит другой.
- `tools/pack_atlas.py`: проверка на реальных кадрах, что атлас не шире 2048,
  все 22 кадра на месте, JSON читается.

Ручная проверка на телефоне по чеклисту: установка на домашний экран, запуск
в авиарежиме, одновременные бег и стрельба, поворот экрана, обновление после
нового деплоя.

## 10. Порядок работы

1. Каркас: Vite + Phaser + TypeScript, пустая сцена с фоном, деплой на Pages.
2. Атлас героя, скрипт упаковки, герой бегает и прыгает по тестовой земле.
3. Парсер уровня, тайлы, ящики, камера, первый уровень.
4. Стрельба, снаряды, ломание ящиков.
5. Зомби-заглушка, патруль, поражение, респаун героя.
6. Тач-управление, HUD, финиш, экран победы, ориентация.
7. PWA: манифест, иконки, офлайн, проверка на телефоне.
8. Подмена заглушки зомби на атлас, когда кадры сгенерированы.
